## 1. 개요

### 1.1 한 줄 정의
해외 프로덕트·UX 디자인 콘텐츠를 운영자가 직접 선정하고, **영어 원문 + 한국어 번역 병기**로 읽으며 영어 표현을 익히고, **내 생각을 기록해 개인 아카이브로 쌓는** 모바일 웹.

### 1.2 문제
- 해외 디자인 동향은 양질의 콘텐츠가 여러 채널(X, LinkedIn, Medium, HN, NN/g, YouTube)에 흩어져 있어 탐색 비용이 크다.
- 영어 원문을 끝까지 읽기 부담스럽고, 읽고 나서도 "읽고 끝"이라 인사이트와 표현이 남지 않는다.

### 1.3 목표
| # | 목표 | 성공 지표(초안) |
|---|---|---|
| G1 | 큐레이션된 해외 디자인 콘텐츠를 한국어로 빠르게 파악 | 상세 진입률, 원문 이동 CTR |
| G2 | 병기 읽기로 끝까지 읽는 경험 제공 | 읽기 완료율(스크롤 90%+), 평균 체류 시간 |
| G3 | 읽기 → 표현 저장 → 생각 기록의 개인 아카이브 루프 형성 | 표현 저장 수/사용자, 코멘트 작성률, 7일 재방문율 |
| G4 | 게스트 사용 → 구글 로그인(백업) 전환 | 게스트 데이터 보유자 중 로그인 전환율 |

### 1.4 비목표 (이번 범위 아님)
- 자동 크롤링/자동 요약/기계 번역 파이프라인 (초기엔 수동 큐레이션 + 검수된 요약 등록)
- 사용자 간 소셜 기능(공유 피드, 팔로우, 공개 코멘트)
- 원문 전체 게재 (원문의 **일부**만 발췌, 나머지는 원문 링크로 이동)
- 네이티브 앱, 푸시 알림
- 간격 반복(SRS) 등 본격 학습 알고리즘 (복습은 "저장해서 모아보기"까지)

## 2. 사용자

**핵심 타깃**: 해외 프로덕트·UX 디자인 정보를 찾는 한국어 사용자(주니어~시니어 디자이너, PM). 영어 독해는 가능하나 속독이 부담스럽고 표현 학습 욕구가 있음.

**원칙: 로그인은 필수가 아니라 "내 기록을 안전하게 보관하고 기기 간 이어보는" 선택 기능이다.**

| 상태 | 가능한 행동 | 데이터 |
|---|---|---|
| 게스트 (로그인 안 함) | **모든 기능 사용 가능**: 열람, 번역 토글, 툴팁, 진행 바, 하이라이트, 코멘트, 표현 저장, 표현/내 생각 탭 | 익명 세션으로 Supabase에 저장 (기기·브라우저 단위) |
| 구글 로그인 | 게스트 기능 전부 + 기기 간 동기화, 브라우저 데이터를 지워도 복구 | 게스트 데이터가 **같은 계정으로 승계**(이전/병합 작업 없음) |

게스트 데이터 정책
- 최초 방문 시 Supabase 익명 로그인(`signInAnonymously`)으로 `user_id`를 발급하고, 이후 모든 기록은 이 `user_id`에 저장한다.
- 구글 로그인은 같은 사용자에 구글 ID를 연결(`linkIdentity`)해 `user_id`를 유지한다. 이미 구글 계정이 다른 기기에서 쓰이고 있다면 게스트 데이터를 기존 계정에 병합하는 처리를 한다.
- 로그인 유도는 막는 팝업이 아니라 "기록 백업" 제안으로, 가치가 쌓인 시점(표현 3개 저장, 첫 코멘트 작성, 읽기 완료 직후)에만 1회씩 노출한다.
- 게스트 데이터는 기기 변경·브라우저 데이터 삭제·iOS Safari의 오래된 사이트 데이터 정리 시 사라질 수 있음을 UI에서 안내한다.

## 3. 콘텐츠 소스 & 운영

| 소스 | 대상 | 비고 |
|---|---|---|
| Figma X 계정 | 게시글 | 포스트 링크 + 발췌 |
| LinkedIn | 게시글 | 포스트 링크 + 발췌 |
| Medium | Product Design 카테고리 인기글 | |
| Hacker News | 디자인 관련 글 | 링크된 원문 기준 |
| NN/g | 아티클 | |
| YouTube | Lenny's Podcast 중 디자인 관계자 영상 | 트랜스크립트 발췌 |

**운영 방식 (MVP)**
1. 운영자가 소스에서 **무료로 공개된 글**만 선정한다.
2. 원문 발췌(문장 단위)를 등록하면 **AI가 번역·요약·주요 표현 초안**을 만든다.
3. 운영자가 검수·수정한 뒤 "검수 완료"로 바꿔야 게시할 수 있다. (AI 초안이 검수 없이 노출되지 않음)
4. 상세 화면에 출처·저자·원문 링크를 항상 표기한다.
5. YouTube(Lenny's Podcast)는 **영상 임베드를 병행**하되 타임스탬프 링크는 제공하지 않고, 트랜스크립트에서 발췌한 문장을 일반 콘텐츠와 동일하게 병기한다.

> ⚠️ **저작권**: 무료 공개 글이라도 자유 이용이 보장되지는 않는다. 발췌는 일부로 제한하고, 출처 표기와 원문 링크를 필수로 한다. 소스별 발췌 분량 가이드를 운영 문서로 정한다.

## 4. 정보 구조 & 화면

### 4.1 하단 탭 (3개)
| 탭 | 설명 |
|---|---|
| **탐색** | 큐레이션 콘텐츠 리스트 (아티클/영상, 소스 필터) |
| **표현** | 저장한 영어 표현 모아보기 |
| **아카이브** | 내 생각(코멘트·하이라이트·읽고 난 생각) / 저장한 글 |

### 4.2 라우트 (Next.js App Router)
```
/                       탐색 (콘텐츠 리스트)
/contents/[id]          콘텐츠 상세 (병기 읽기)
/expressions            저장한 표현
/archive               아카이브 (내 생각 / 저장한 글)
/mypage                 마이페이지 (프로필, 설정, 로그아웃)
/login                  로그인 (또는 바텀시트)
/admin/*                운영자 등록 (MVP: 간이/보호)
```

### 4.3 화면 요약
**A. 홈 (리스트)**
- 카드: 썸네일(옵션), 소스 배지, 한국어 제목, 한 줄 요약, 읽는 시간, 날짜
- 소스 필터 칩: 전체 / Figma / LinkedIn / Medium / Hacker News / NN/g / YouTube

**B. 콘텐츠 상세**
- 상단 고정 영역: 뒤로가기, **읽기 진행 프로그레스 바**, 번역 토글
- 헤더: 제목(KO/EN), 소스·저자·원문 링크
- 본문: 문장 단위로 EN → KO 병기 (번역 off 시 EN만)
- 주요 표현: 하이라이트 표시 → 탭하면 **툴팁**(뜻, 품사/예문)
- 일반 문장 탭: 액션 시트 → 하이라이트 / 코멘트
- 본문 끝: **「이 글의 주요 표현」** 정리 섹션 (표현 저장 버튼)
- 최하단: **「내 생각」** (내가 남긴 코멘트 목록 + 입력 필드)
- 원문 보러가기 CTA (상단/하단)

**C. 표현 탭**: 저장 표현 리스트(표현, 뜻, 예문, 출처 글 링크, 삭제), 검색/정렬

**D. 내 생각 탭**: 글별 그룹 또는 시간순, 하이라이트 문장 + 코멘트, 클릭 시 해당 글 위치로 이동, 수정/삭제

```
               (모든 사용자 데이터는 RLS로 본인 user_id만 접근)
SavedExpression  user_id, expression_id, saved_at
UserHighlight  id, user_id, sentence_id, created_at
Comment        id, user_id, content_id, sentence_id?(null=글 단위 메모),
               body, created_at, updated_at
ReadingState   user_id, content_id, progress, completed_at   (P1)
```

- 문장 단위 `Sentence`를 기본 단위로 삼아 번역 병기·하이라이트·코멘트의 앵커로 통일한다.
- 표현 하이라이트는 문장 내 문자 오프셋(`start`,`end`)으로 지정한다.

## 8. 기술 요구사항

### 8.1 스택
| 영역 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | **Next.js (App Router, TypeScript)** | 리스트/상세는 SSG/ISR + 사용자 데이터는 클라이언트/Route Handler |
| 스타일 | **Tailwind CSS** | 디자인 토큰은 `tailwind.config`로 관리, 다크모드 대비 |
| 인증/DB | **Supabase** (Auth: 익명 로그인 + Google, Postgres, RLS) | 확정 |
| AI 번역 | Claude API (서버/어드민에서만 호출) | 번역·요약·표현 초안 생성, 운영자 검수 필수 |
| 배포 (제안) | Vercel | |
| 분석 (제안) | Amplitude / Mixpanel / GA4 중 택1 | |

### 8.2 구현 가이드
- **렌더링**: 콘텐츠 상세는 정적 생성(ISR)으로 비로그인 열람·SEO 확보, 개인화 요소(하이라이트·코멘트·저장 상태)는 클라이언트에서 로그인 후 hydrate.
- **프로그레스 바**: 본문 컨테이너 기준 `IntersectionObserver`/스크롤 이벤트(throttle, rAF)로 계산.
- **툴팁/액션 시트**: 모바일 터치 기준 바텀시트 컴포넌트, 접근성(포커스 트랩, ESC/뒤로가기 닫기).
- **번역 토글**: 전역 상태(Context/Zustand) + localStorage, Tailwind 조건부 클래스로 KO 라인 숨김.
- **디자인 시안 → 프로토타입**: 우선 mock JSON 데이터와 localStorage로 로그인/저장/코멘트 흐름이 동작하는 프로토타입을 만들고, 이후 실제 백엔드로 교체한다.

### 8.3 비기능

3. 소스별 발췌 분량 가이드(문장 수/비율) 확정.
4. 어드민을 운영하는 사람이 본인 1인인지, 이후 다른 사람이 추가되는지.
5. 게스트 데이터 보존 기간(미사용 익명 계정 정리 주기).

## 부록 A. 어드민 방식 비교

| | Notion 연동 | 헤드리스 CMS (Sanity 등) | Supabase 대시보드 직접 편집 | **자체 최소 어드민** |
|---|---|---|---|---|
| 익숙함 | 높음 | 보통 | 낮음 (DB 표 화면) | 직접 설계 가능 |
| 문장 단위 EN/KO 검수 | 어려움 | 가능하나 커스텀 필요 | 행 단위라 불편 | **맞춤 설계 가능** |
| 텍스트 드래그로 표현 지정 | 불가 | 커스텀 필요 | 불가 | **가능** |
| AI 번역 → 검수 → 게시 흐름 | 별도 자동화 필요 | 플러그인/커스텀 | 불가 | **한 화면에서 가능** |
| 데이터 동기화 | Notion → Supabase 동기화 필요 | CMS → Supabase 동기화 필요 | 불필요 | **불필요 (Supabase 직접)** |
| 추가 비용/서비스 | Notion 플랜 | CMS 플랜 | 없음 | 없음 |
| 초기 개발량 | 중 | 중~대 | 없음 | 중 |

**선택: 자체 최소 어드민.** 이 서비스의 운영 핵심은 "AI 번역 초안을 문장별로 나란히 보며 고치고, 본문에서 표현을 드래그해 지정하는 것"인데, 범용 CMS는 이 작업 화면을 그대로 제공하지 못해 결국 커스텀이 필요하고 데이터 동기화도 늘어난다.

**어드민 화면 (3개)**
1. 콘텐츠 목록: 상태(초안/검수 완료/게시) 필터
2. 등록·검수: 메타 입력 → 원문 붙여넣기 → AI 번역 → 문장별 나란히 수정 → 표현 지정
3. 미리보기·게시: 모바일 화면으로 확인 후 게시

**단계**
- M0 프로토타입: 어드민 없이 mock JSON 사용
- M1 초반: Supabase 대시보드로 직접 입력해 서비스 흐름 검증
- M1 본격: 위 3개 화면 구현
