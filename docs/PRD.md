## 1. 개요

### 1.1 한 줄 정의
해외 프로덕트·UX 디자인 콘텐츠를 운영자가 직접 선정하고, **영어 원문 + 한국어 번역 병기**로 읽으며 인사이트를 얻고, **내 생각을 기록해 개인 아카이브로 쌓는** 모바일 웹.

### 1.2 문제
- 해외 디자인 동향은 양질의 콘텐츠가 여러 채널(Figma 블로그, Medium, HN, NN/g, YouTube)에 흩어져 있어 탐색 비용이 크다.
- 영어 원문을 끝까지 읽기 부담스럽고, 읽고 나서도 "읽고 끝"이라 인사이트가 남지 않는다.

### 1.3 목표
| # | 목표 | 성공 지표(초안) |
|---|---|---|
| G1 | 큐레이션된 해외 디자인 콘텐츠를 한국어로 빠르게 파악 | 상세 진입률, 원문 이동 CTR |
| G2 | 병기 읽기로 끝까지 읽는 경험 제공 | 읽기 완료율(스크롤 90%+), 평균 체류 시간 |
| G3 | 읽기 → 하이라이트·코멘트 → 생각 기록의 개인 아카이브 루프 형성 | 하이라이트·코멘트 수/사용자, 코멘트 작성률, 7일 재방문율 |
| G4 | 게스트 사용 → 구글 로그인(백업) 전환 | 게스트 데이터 보유자 중 로그인 전환율 |

### 1.4 비목표 (이번 범위 아님)
- 자동 크롤링/자동 요약/기계 번역 파이프라인 (초기엔 수동 큐레이션 + 검수된 요약 등록)
- 사용자 간 소셜 기능(공유 피드, 팔로우, 공개 코멘트)
- 원문 전체 게재 (원문의 **일부**만 발췌, 나머지는 원문 링크로 이동)
- **YouTube 영상 임베드** (영상 콘텐츠도 트랜스크립트 발췌 문장만 제공)
- 네이티브 앱, 푸시 알림
- 간격 반복(SRS) 등 본격 학습 알고리즘 (복습은 "저장해서 모아보기"까지)

## 2. 사용자

**핵심 타깃**: 해외 프로덕트·UX 디자인 정보를 찾는 한국어 사용자(주니어~시니어 디자이너, PM). 영어 독해는 가능하나 속독이 부담스럽고, 읽은 글에서 업무에 쓸 인사이트를 얻고 싶어 함.

**원칙: 로그인은 필수가 아니라 "내 기록을 안전하게 보관하고 기기 간 이어보는" 선택 기능이다.**

| 상태 | 가능한 행동 | 데이터 |
|---|---|---|
| 게스트 (로그인 안 함) | **모든 기능 사용 가능**: 열람, 번역 토글, 진행 바, 하이라이트, 코멘트, 내 생각, 글 저장, 아카이브 4개 필터, 피드백 | 익명 세션으로 Supabase에 저장 (기기·브라우저 단위) |
| 구글 로그인 | 게스트 기능 전부 + 기기 간 동기화, 브라우저 데이터를 지워도 복구, 구글 프로필 사진 표시 | 게스트 데이터가 **같은 계정으로 승계**(이전/병합 작업 없음) |

게스트 데이터 정책
- 최초 방문 시 Supabase 익명 로그인(`signInAnonymously`)으로 `user_id`를 발급하고, 이후 모든 기록은 이 `user_id`에 저장한다.
- 구글 로그인은 같은 사용자에 구글 ID를 연결(`linkIdentity`)해 `user_id`를 유지한다. 이미 구글 계정이 다른 기기에서 쓰이고 있다면 게스트 데이터를 기존 계정에 병합하는 처리를 한다.
- 로그인 진입점은 두 가지다. ① **프로필 페이지**(앱 바의 프로필 아이콘을 누르면 비로그인도 들어간다. "Google로 로그인하기" 버튼과 그 아래 안내 문구가 있다), ② 가치가 쌓인 시점의 "기록 백업" 제안(바텀시트). 막는 팝업은 없다.
- "기록 백업" 제안은 **첫 코멘트 작성** 시점에만 1회 노출한다. (v0.2의 "읽기 완료 직후", v0.3.1의 "표현 3개 저장"은 삭제)
- 게스트 데이터는 기기 변경·브라우저 데이터 삭제·iOS Safari의 오래된 사이트 데이터 정리 시 사라질 수 있다. (화면 안내 문구는 현재 없음 → 공개 전 안내 방식 결정, §12)

## 3. 콘텐츠 소스 & 운영

| 소스 | 대상 | 비고 |
|---|---|---|
| Figma 블로그 | 블로그 아티클 | 글 링크 + 발췌 |
| Medium | Product Design 카테고리 인기글 | |
| Hacker News | 디자인 관련 글 | 링크된 원문 기준 |
| NN/g | 아티클 | |
| YouTube | Lenny's Podcast 중 디자인 관계자 영상 | 트랜스크립트 발췌 (영상 임베드 없음) |

**운영 방식 (MVP)**
1. 운영자가 소스에서 **무료로 공개된 글**만 선정한다.
2. 원문 발췌(문장 단위)를 등록하면 **AI가 번역·요약 초안**을 만든다.
3. 운영자가 검수·수정한 뒤 "검수 완료"로 바꿔야 게시할 수 있다. (AI 초안이 검수 없이 노출되지 않음)
4. 상세 화면에는 **출처·발행일·원문 링크**를 표기한다. (작성자명은 화면에 표시하지 않음 → §12 확인)
5. YouTube(Lenny's Podcast)는 영상을 임베드하지 않고, 트랜스크립트에서 발췌한 문장을 일반 콘텐츠와 동일하게 병기한다. 원문(영상) 링크는 "원문 읽기" 버튼으로 연결한다.
6. 글마다 **주제**(디자인 프로세스·협업·UX 원칙·디자인 시스템 중 하나)를 지정한다.

> ⚠️ **저작권**: 무료 공개 글이라도 자유 이용이 보장되지는 않는다. 발췌는 일부로 제한하고, 출처 표기와 원문 링크를 필수로 한다. 소스별 발췌 분량 가이드를 운영 문서로 정한다.

## 4. 정보 구조 & 화면

### 4.1 하단 탭 (2개)
| 탭 | 설명 |
|---|---|
| **탐색** | 큐레이션 콘텐츠 리스트 (주제 필터) |
| **아카이브** | 내 기록 모아보기. 필터 4개: **하이라이트 · 코멘트 · 내 생각 · 아티클(저장한 글)** |

탭바는 화면 아래에 떠 있는 알약형이고 아카이브 아이콘은 북마크 모양이다.

### 4.2 라우트 (Next.js App Router)
```
/                       탐색 (콘텐츠 리스트, ?topic= 으로 필터 유지)
/contents/[id]          콘텐츠 상세 (병기 읽기)
/archive                아카이브 (필터 4개)
/expressions            (옛 주소, 표현 기능 삭제 후에도 링크 보존용) /archive 로 이동
/mypage                 프로필 (비로그인도 열림. 로그인 버튼은 프로필 페이지, 백업 제안은 바텀시트)
                        별도 /login 페이지 없음
/admin/*                운영자 등록 (MVP: 간이/보호)
```

### 4.3 화면 요약
**A. 탐색 (리스트)**
- 상단 고정: 앱 바("crumbit" + 프로필 아이콘) + 주제 필터 칩(전체 / 디자인 프로세스 / 협업 / UX 원칙 / 디자인 시스템). 스크롤해도 앱 바와 칩이 위에 붙어 있다.
- 카드: 주제 뱃지, 영어 제목, 한글 제목, 출처·발행일(별 아이콘), 글 저장 아이콘
- 프로필 아이콘: 비로그인은 회색 기본 아이콘, 로그인 후에는 구글 프로필 사진. **둘 다 누르면 프로필 페이지로 이동**한다(로그인 시트는 열지 않는다)

**B. 콘텐츠 상세**
- 상단 고정 영역: 뒤로가기, **읽기 진행 프로그레스 바**, "번역 켜기" 토글, 글 저장
- 헤더: 주제 뱃지, 영어 제목·한글 제목, 출처·발행일 + "원문 읽기" 버튼(새 탭, 상단 1곳)
- **원문 요약** 카드 (운영자가 검수한 요약)
- 본문: 문장 단위로 영어(18px) → 한글 번역(14px) 병기 (번역 off 시 영어만). 문단 사이에 **소제목**(영어 + 한글)을 둘 수 있다
- 일반 문장 탭: **팝오버**(§5.4 규칙)
- 본문 끝 → **「내 생각」**: 이 글에 남긴 생각 목록(작성 날짜 포함) + 입력창("느낀 점, 내 일에 적용해볼 점은?", 안내 "입력한 내용은 나만 봐요.", "생각 남기기" 버튼). 화면의 맨 아래 구획이다

**C. 아카이브** (필터 칩 4개, 칩 영역 고정. 칩에 개수는 표기하지 않는다)
- 하이라이트: 글(주제 뱃지·제목) 단위 그룹 → 하이라이트한 문장 카드(영어 + 한글 번역), 해제
- 코멘트: 글 단위 그룹 → 문장(하이라이트 없음) + 번역 + 코멘트 말풍선, 수정·삭제
- 내 생각: 글 단위 그룹 → 생각 카드(작성 날짜), 수정·삭제
- 아티클: 저장한 글 카드(탐색과 같은 카드). 저장 해제해도 그 화면에서는 카드가 남고 아이콘만 바뀌며, 화면을 벗어났다 돌아오면 사라진다
- 빈 상태(기록이 없을 때): 가운데 정렬로 **제목 + "글 읽으러 가기" 버튼**. 하이라이트("아티클에서 기억하고 싶은 문장을 눌러 하이라이트해 보세요.")와 코멘트("아티클에서 생각을 남기고 싶은 문장을 눌러 코멘트해 보세요.")만 제목 아래에 한 줄 안내(`body-sm`, 회색)를 둔다. 내 생각·아티클은 제목만 둔다

**D. 프로필**
- 로그인 후: 구글 프로필 사진(80px), 로그인 이메일, 번역 항상 켜기(토글), 피드백 보내기, 로그아웃, 계정 삭제
- 비로그인: 회색 기본 아이콘(80px) → **"Google로 로그인하기" 버튼**(좌우 여백 32px, 내용 폭에 맞춤) → 안내 "로그인하면 다른 기기에서도 내 기록을 볼 수 있어요."(`body-sm`), 그 아래 번역 항상 켜기, 피드백 보내기(로그아웃·계정 삭제는 없음)

**E. 시트·다이얼로그**
- 로그인 바텀시트(기록 백업 제안: 첫 코멘트 때만 자동으로 뜸. 시트 안 버튼은 "Google로 계속하기")
- 코멘트 바텀시트 (대상 문장 + 번역 + 입력)
- 삭제 확인 다이얼로그 (모든 삭제 공통: "삭제할까요?" / "삭제하면 되돌릴 수 없어요.")
- 피드백 다이얼로그 (유형 칩 5개 + 내용)

## 5. 기능 요구사항

우선순위: **P0** = MVP 필수, **P1** = MVP 이후 빠르게, **P2** = 후보

### 5.1 콘텐츠 열람
| ID | 요구사항 | 우선순위 |
|---|---|---|
| F-01 | 비로그인 상태에서 리스트·상세 열람 가능 | P0 |
| F-02 | 리스트에서 **주제별** 필터링, 필터 칩은 스크롤해도 상단에 고정 | P0 |
| F-03 | 상세에서 원문 일부를 영어/한국어 병기로 표시 | P0 |

## 8. 기술 요구사항

### 8.1 스택
| 영역 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | **Next.js (App Router, TypeScript)** | 리스트/상세는 SSG/ISR + 사용자 데이터는 클라이언트/Route Handler |
| 스타일 | **Tailwind CSS v4** + shadcn/ui(Base UI) | 디자인 토큰 원본은 `DESIGN.md`, 실제 값은 `app/globals.css`의 `@theme` |
| 인증/DB | **Supabase** (Auth: 익명 로그인 + Google, Postgres, RLS) | 확정 |
| AI 번역 | Claude API (서버/어드민에서만 호출) | 번역·요약 초안 생성, 운영자 검수 필수 |
| 배포 | Vercel (GitHub 연결) | 브랜치 푸시 → Preview, main → Production |
| 분석 | Mixpanel + Amplitude | 이벤트 정의는 `docs/analytics-events.md` |

### 8.2 구현 가이드
- **렌더링**: 콘텐츠 상세는 정적 생성(ISR)으로 비로그인 열람·SEO 확보, 개인화 요소(하이라이트·코멘트·저장 상태)는 클라이언트에서 로그인 후 hydrate.
- **프로그레스 바**: 본문 컨테이너 기준 스크롤 이벤트(rAF)로 계산.
- **팝오버**: 문장 블록 안에서 위치를 계산해 띄운다. 로그인·코멘트는 바텀시트, 삭제·피드백은 다이얼로그.
- **번역 토글**: 전역 상태 + localStorage. 연결 후에는 `user_settings`에도 저장.
- **사용자 기록 저장**: 화면은 로컬 상태를 먼저 바꾸고(localStorage), 서버로 보낼 변경은 `lib/remote.ts`의 편지함(outbox, localStorage)에 쌓아 순서대로 전송한다. 네트워크가 끊겨도 남아 있다가 연결이 돌아오면 보낸다. Supabase 키가 없으면 localStorage만 쓰는 프로토타입 모드로 동작한다.
- **기록 합치기**: 이 기기에서 처음 연결하거나 다른 계정으로 로그인하면 로컬 기록을 서버에 합집합으로 올린 뒤 서버 기록을 받아온다(F-73의 기본 처리).
- **콘텐츠 데이터**: M0.5는 `data/raw.ts`. 진짜 아티클 1~2개를 이 파일에 넣어 검증한 뒤, 사용자 기록과 함께 Supabase로 옮긴다(§11). 문단은 문장 쌍의 배열, 소제목은 `{ h: [영어, 한글] }`, 건너뛴 자리는 `{ gap: true }`.
- **배포 전 점검**: `npm run build`를 통과해야 한다. 린트·자동 테스트 스크립트는 아직 없다(추가 예정, §11).

### 12.2 남은 확인 사항
1. 번역 톤 가이드(직역/의역, 용어 통일: 예 "design system"은 번역 vs 원어 유지)를 정할 것.
2. 소스별 발췌 분량 가이드(문장 수/비율) 확정.
3. 어드민을 운영하는 사람이 본인 1인인지, 이후 다른 사람이 추가되는지.
4. 게스트 데이터 보존 기간(미사용 익명 계정 정리 주기).
5. 화면에서 **작성자명을 표시하지 않는** 변경이 출처 표기 원칙(§3)과 충돌하지 않는지.
6. 저장소·Vercel 프로젝트 이름(`articles`)과 도메인을 서비스명에 맞출지.
7. F-74(로그아웃·계정 삭제)를 P0로 올릴지.
8. 게스트 데이터가 사라질 수 있다는 안내를 화면 어디에 둘지(현재 안내 배너 삭제됨).

## 부록 A. 어드민 방식 비교

| | Notion 연동 | 헤드리스 CMS (Sanity 등) | Supabase 대시보드 직접 편집 | **자체 최소 어드민** |
|---|---|---|---|---|
| 익숙함 | 높음 | 보통 | 낮음 (DB 표 화면) | 직접 설계 가능 |
| 문장 단위 EN/KO 검수 | 어려움 | 가능하나 커스텀 필요 | 행 단위라 불편 | **맞춤 설계 가능** |
| AI 번역 → 검수 → 게시 흐름 | 별도 자동화 필요 | 플러그인/커스텀 | 불가 | **한 화면에서 가능** |
| 데이터 동기화 | Notion → Supabase 동기화 필요 | CMS → Supabase 동기화 필요 | 불필요 | **불필요 (Supabase 직접)** |
| 추가 비용/서비스 | Notion 플랜 | CMS 플랜 | 없음 | 없음 |
| 초기 개발량 | 중 | 중~대 | 없음 | 중 |

**선택: 자체 최소 어드민.** 이 서비스의 운영 핵심은 "AI 번역 초안을 문장별로 나란히 보며 고치는 것"인데, 범용 CMS는 이 작업 화면을 그대로 제공하지 못해 결국 커스텀이 필요하고 데이터 동기화도 늘어난다.

**어드민 화면 (3개)**
1. 콘텐츠 목록: 상태(초안/검수 완료/게시) 필터
2. 등록·검수: 메타 입력 → 원문 붙여넣기 → AI 번역 → 문장별 나란히 수정
3. 미리보기·게시: 모바일 화면으로 확인 후 게시

**단계**
- M0 프로토타입: 어드민 없이 mock JSON 사용
- M0.5: 진짜 아티클 1~2개를 `data/raw.ts`에 직접 입력해 검증
- M1 초반: Supabase 대시보드로 직접 입력해 서비스 흐름 검증
- M1 본격: 위 3개 화면 구현
